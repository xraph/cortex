The SQLite store (`store/sqlite`) provides a lightweight, embedded backend using the [Grove ORM](https://github.com/xraph/grove) with `sqlitedriver`. It implements the full `store.Store` composite interface and is well-suited for single-process deployments, local development, and testing.

## Setup

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    _ "github.com/xraph/grove/drivers/sqlitedriver/sqlitemigrate"

    "github.com/xraph/cortex/store/sqlite"
)

// Open a SQLite database through Grove's sqlitedriver.
drv := sqlitedriver.New()
if err := drv.Open(ctx, "cortex.db"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := sqlite.New(db)
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

The blank `sqlitemigrate` import registers Grove's migration executor for SQLite. Without it `Migrate` fails with "no executor registered for driver".

If you turn on agent messaging (`engine.WithA2A`), set a busy timeout in the DSN, for example `cortex.db?_pragma=busy_timeout(5000)`. The message dispatcher writes from its own goroutines, and SQLite answers a concurrent writer with `SQLITE_BUSY` unless it's told to wait.

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | Grove ORM with `sqlitedriver` (SQLite) |
| Migrations | Grove migration orchestrator with programmatic migrations |
| Transactions | Database-level transactions via SQLite |

## Tables

The SQLite store creates the same tables as the PostgreSQL store:

| Table | Entity |
|-------|--------|
| `cortex_agents` | Agent configs |
| `cortex_skills` | Skills |
| `cortex_traits` | Traits |
| `cortex_behaviors` | Behaviors |
| `cortex_personas` | Personas |
| `cortex_runs` | Runs |

## Composite store interface

The SQLite store implements all 14 sub-interfaces:

```go
type Store interface {
    agent.Store               // 7 methods
    run.Store                 // 9 methods
    memory.Store              // 8 methods
    checkpoint.Store          // 5 methods
    skill.Store               // 7 methods
    trait.Store               // 7 methods
    behavior.Store            // 7 methods
    persona.Store             // 7 methods
    prompt.Store              // 7 methods
    session.Store             // 6 methods
    suspension.Store          // 7 methods
    orchestration.ConfigStore // 7 methods
    orchestration.RunStore    // 5 methods
    a2a.Store                 // 20 methods

    Migrate(ctx context.Context, opts ...cortex.MigrateOption) error
    Ping(ctx context.Context) error
    Close() error
}
```

## Usage with engine

```go
eng, err := engine.New(
    engine.WithStore(s),
)
```

## When to use

- Local development: a single-file database, no server process required.
- Testing: a fast, isolated store with no external dependencies.
- Embedded or single-process apps: CLI tools, desktop apps or edge deployments.
- CI pipelines: deterministic tests without a database container.
