The MongoDB store (`store/mongo`) provides a document-oriented backend using the [Grove ORM](https://github.com/xraph/grove) with `mongodriver`. It stores Cortex entities in 19 MongoDB collections, with compound indexes for queries scoped by `cortex.Scope`.

## Setup

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/mongodriver"

    "github.com/xraph/cortex/store/mongo"
)

// Open a MongoDB connection through Grove's mongodriver. The database
// name comes from the URI path.
drv := mongodriver.New()
if err := drv.Open(ctx, "mongodb://localhost:27017/cortex?replicaSet=rs0"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

s := mongo.New(db)
if err := s.Migrate(ctx); err != nil {
    log.Fatal(err)
}
```

Use a replica set or a sharded cluster. Saving or clearing a conversation writes the messages and the session's counters in one multi-document transaction, and a standalone `mongod` can't run transactions, so every conversation write fails against one.

## Internals

| Aspect | Detail |
|--------|--------|
| Driver | Grove ORM with `mongodriver` (MongoDB) |
| Migrations | `Migrate` creates the indexes (idempotently) and runs the rescope and session backfill. There's no schema validation |
| Transactions | Single-document writes are atomic. Conversation writes use a multi-document transaction |

```go
    session.Store             // 6 methods
    suspension.Store          // 7 methods
    orchestration.ConfigStore // 7 methods
    orchestration.RunStore    // 5 methods

}
```

## Usage with engine

```go
eng, err := engine.New(
    engine.WithStore(s),
)
```

## Migrations

MongoDB has no DDL to version, so unlike the PostgreSQL and SQLite stores this one exports no Grove `Migrations` group. `Migrate` creates every collection's indexes with an idempotent `CreateMany` on each call, then runs the same rescope pass and default-session backfill the other backends do. Call it on startup, or let the Forge extension call it for you.

## When to use

- Document-oriented workloads: flexible schemas that evolve with your application.
- Horizontal scaling: MongoDB sharding for large deployments.
- Managed hosting: MongoDB Atlas.
- Teams already running MongoDB.
