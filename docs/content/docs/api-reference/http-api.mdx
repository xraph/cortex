---
title: HTTP API Reference
description: Reference for the Cortex REST endpoints, covering agents, runs, skills, traits, behaviors, personas, checkpoints, memory, sessions, tools, orchestrations, and configuration.
---

All endpoints live under `<basePath>/v1` and return JSON. `basePath` is the extension mount prefix (`extension.WithBasePath`, default `/cortex`) and `/v1` is the API version group, so the default full path is `/cortex/v1/...`. Authentication and tenant resolution depend on your middleware configuration. Set `X-Tenant-ID` and `X-App-ID` headers for multi-tenant deployments.

## Agents (8 routes)

### `POST /cortex/v1/agents`

Create an agent configuration.

**Request**

```json
{
  "name": "support-agent",
  "description": "Customer support agent",
  "system_prompt": "You are a helpful support agent.",
  "model": "gpt-4o",
  "tools": ["lookup_order", "create_ticket"],
  "max_steps": 15,
  "max_tokens": 4096,
  "temperature": 0.7,
  "reasoning_loop": "react",
  "persona_ref": "helpful-agent",
  "inline_skills": ["customer-support"],
  "inline_traits": ["empathy"],
  "inline_behaviors": ["auto-escalate"],
  "guardrails": {},
  "metadata": {}
}
```

**Response** `201 Created` — Agent object with generated `id` (e.g. `agt_01h455...`).

---

### `GET /cortex/v1/agents`

List all agents for the current tenant/app.

**Query parameters**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `limit` | int | 50 | Max results |
| `offset` | int | 0 | Pagination offset |

**Response** `200 OK` — Array of Agent objects.

---

### `GET /cortex/v1/agents/:name`

Get an agent by name.

**Response** `200 OK` — Agent object.

**Error** `404 Not Found` if agent does not exist.

---

### `PUT /cortex/v1/agents/:name`

Update an agent configuration. Only provided fields are updated.

**Request** — Same shape as create, all fields optional except `name` (path).

**Response** `200 OK` — Updated Agent object.

---

### `DELETE /cortex/v1/agents/:name`

Delete an agent configuration.

**Response** `204 No Content`

---

### `POST /cortex/v1/agents/:name/run`

Execute an agent synchronously. Returns when the run completes.

**Request**

```json
{
  "input": "I want to return order #12345"
}
```

**Response** `200 OK`

```json
{
  "run_id": "arun_01h455...",
  "state": "completed",
  "output": "I'd be happy to help with your return...",
  "step_count": 3,
  "tokens_used": 1240
}
```

---

### `POST /cortex/v1/agents/:name/stream`

Execute an agent with Server-Sent Events (SSE) streaming.

**Request** — Same as `/run`.

**Response** `200 OK` with `Content-Type: text/event-stream`.

---

### `POST /cortex/v1/agents/:name/clone`

Clone an agent into a new, independent copy in the same app. All configuration is copied; the clone gets a fresh `id`, fresh timestamps, and no runtime history (runs/memory/conversation stay with the source). The clone keeps the same `persona_ref` (the persona is shared, not copied).

**Request**

```json
{
  "new_name": "support-agent-v2"
}
```

`new_name` is optional. If omitted, a unique name is generated: `<source>-copy`, then `<source>-copy-2`, `<source>-copy-3`, … until one is free.

**Response** `201 Created` — the new Agent object.

**Errors** — `404 Not Found` if the source agent does not exist; `409 Conflict` if `new_name` is already taken.

### `GET /cortex/v1/runs/:id`

Get a specific run by ID.

**Response** `200 OK`

```json
{
  "id": "arun_01h455...",
  "agent_id": "agt_01h455...",
  "scope": {
    "levels": [
      { "key": "workspace", "value": "acme-corp" },
      { "key": "project", "value": "support-bot" }
    ]
  },
  "state": "completed",
  "input": "I want to return order #12345",
  "output": "I'd be happy to help...",
  "error": "",
  "step_count": 3,
  "tokens_used": 1240,
  "started_at": "2024-01-15T10:30:00Z",
  "completed_at": "2024-01-15T10:30:05Z",
  "persona_ref": "helpful-agent",
  "metadata": {}
}
```

`tenant_id` no longer serializes — as of v1.7.0 a run carries `scope`, a
host-defined ordered hierarchy, instead of a single tenant string. See
[Multi-tenancy](/docs/concepts/multi-tenancy).

---

### `POST /cortex/v1/runs/:id/cancel`

Cancel a run that is still running or paused. Sets state to `cancelled`.

A paused run is claimed before it's written, the same way a resume claims it, so
a cancel arriving while somebody is already resuming or deciding that run loses
and comes back `409`. The cancel that wins drops the run's suspension and
resolves whatever checkpoint the pause opened. A run that already finished is
`400`.

**Response** `204 No Content`

## Checkpoints (2 routes)

### `GET /cortex/v1/checkpoints`

List pending checkpoints (runs paused for human approval).

**Query parameters** — `limit`, `offset`.

**Response** `200 OK` — Array of Checkpoint objects.

---

### `POST /cortex/v1/checkpoints/:id/resolve`

Resolve a checkpoint.

**Request**

```json
{
  "decision": "approved",
  "decided_by": "admin@acme.com",
  "reason": "checked the ticket, it is the right cluster"
}
```

`reason` is optional. On a rejection it lands on the run's `error` field, so
whoever finds the failed run later reads why a person stopped it. An approval
resumes the run synchronously, so this request stays open for as long as the
rest of the run takes.

**Response** `200 OK`

## Sessions (6 routes)

A session is one conversation thread for an agent. Runs join a session, and
memory is read and written per session.

### `GET /cortex/v1/agents/:name/sessions`

### `GET /cortex/v1/agents/:name/sessions/count`

### `PUT /cortex/v1/agents/:name/sessions/:id`

### `DELETE /cortex/v1/agents/:name/sessions/:id`

## Orchestrations (8 routes)

Multi-agent orchestration. A stored orchestration config names a **strategy** and its **participant agents**; running it coordinates those agents over a shared blackboard. See the [Orchestration guide](/docs/execution/orchestration) for concepts.

### `POST /cortex/v1/orchestrations`

Create an orchestration config.

**Request**

```json
{
  "name": "should-we-ship",
  "description": "Ship-decision debate",
  "strategy": "debate",
  "participants": [
    {"agent_name": "optimist", "role": "debater"},
    {"agent_name": "skeptic", "role": "debater"},
    {"agent_name": "referee", "role": "judge"}
  ],
  "settings": {"rounds": 2, "judge": "referee"},
  "metadata": {}
}
```

`strategy` is one of `sequential`, `parallel`, `router`, `hierarchical`, `debate`. `settings` fields are strategy-specific (`max_concurrency`, `rounds`, `manager`, `judge`, `aggregator`, `router_agent`, `router_rules`, `model`) — each strategy reads only what it needs.

**Response** `201 Created` — Orchestration object with generated `id` (e.g. `orchcfg_01h455...`).

**Errors** — `400 Bad Request` if `strategy` is unknown or `participants` is empty.

---

### `GET /cortex/v1/orchestrations`

List orchestration configs.

**Query parameters** — `limit`, `offset`.

**Response** `200 OK` — Array of Orchestration objects.

---

### `GET /cortex/v1/orchestrations/:name`

Get an orchestration config by name.

**Response** `200 OK` — Orchestration object. `404 Not Found` if it does not exist.

---

### `PUT /cortex/v1/orchestrations/:name`

Update an orchestration config. Only provided fields are updated.

**Response** `200 OK` — Updated Orchestration object.

---

### `DELETE /cortex/v1/orchestrations/:name`

Delete an orchestration config.

**Response** `204 No Content`

---

### `POST /cortex/v1/orchestrations/:name/run`

Run a stored orchestration. Executes the strategy across its participant agents and persists an orchestration run.

**Request**

```json
{
  "input": "Should we ship the feature this week?"
}
```

**Response** `200 OK`

```json
{
  "run_id": "orch_01h455...",
  "status": "completed",
  "strategy": "debate",
  "output": "...the judge's verdict...",
  "duration_ms": 4213
}
```

A run that executes but whose strategy fails still returns `200 OK` with `"status": "failed"` (it is not an HTTP error). `404 Not Found` is returned only when the orchestration config does not exist.

---

### `GET /cortex/v1/orchestration-runs`

List orchestration run records.

**Query parameters** — `limit`, `offset`, `status` (filter: `running` | `completed` | `failed`).

**Response** `200 OK` — Array of orchestration run objects.

---

### `GET /cortex/v1/orchestration-runs/:id`

Get an orchestration run by ID.

**Response** `200 OK` — orchestration run object. `404 Not Found` if it does not exist.

## Error format

All error responses use a consistent JSON envelope:

```json
{
  "error": "human-readable message",
  "code": "ERROR_CODE"
}
```

| HTTP status | `code` | Cause |
|-------------|--------|-------|
| `400` | `BAD_REQUEST` | Missing required field, invalid input |
| `404` | `NOT_FOUND` | Entity not found for tenant |
| `409` | `ALREADY_EXISTS` | Entity with that name already exists |
| `500` | `INTERNAL_ERROR` | Store or engine failure |
