The REST handlers live in their own module, `github.com/xraph/cortex/api`, and the Forge extension mounts none of them unless you ask it to:

```go
import (
    "github.com/xraph/forge"

    "github.com/xraph/cortex/api"
    "github.com/xraph/cortex/engine"
    cortexext "github.com/xraph/cortex/extension"
)

cortexExt := cortexext.New(
    cortexext.WithRoutes(func(eng *engine.Engine, r forge.Router) cortexext.RouteSet {
        return api.New(eng, r)
    }),
)
```

That gives you the 59 routes on this page. They live under `<basePath>/v1` and return JSON. `basePath` is the extension's mount prefix (`extension.WithBasePath` or `base_path`, default `/cortex`) and `/v1` is the version group every handler registers in, so the default full path is `/cortex/v1/...`. If you serve `api.New(eng, router)` on a router of your own instead, the paths start at `/v1`.

Cortex doesn't authenticate requests or work out who's calling. Your middleware has to put a `cortex.Scope` on each request's context with `cortex.WithScope` (and optionally a principal with `cortex.WithPrincipal`) before it reaches these handlers. Without a scope every route fails. The `X-Tenant-ID` headers in the examples on other pages are whatever your own middleware reads; Cortex doesn't look at any header. See [Forge Extension](/docs/guides/forge-extension#scope-middleware).

### Authorizing requests

Pass `api.WithAuthorizer` to put every route behind a check of your own:

```go
return api.New(eng, r, api.WithAuthorizer(myAuthorizer))
```

An `api.Authorizer` has two methods. `Authorize(ctx, op)` runs before each route with the request's context and an `api.Operation`: `ID` is the route's OpenAPI operation id (`resolveCheckpoint`, `listTools` and so on) and `Write` is true for anything other than `GET` or `HEAD`. Return nil to let the request through. Any other error refuses it with `403`, and the response never repeats your error's text. The one exception is an error that wraps a Cortex not-found or scope error: that keeps the status it has everywhere else, so `cortex.ErrAgentNotFound` is still a `404` and `cortex.ErrNoScope` a `412`. `DecidedBy(ctx)` names the person resolving a checkpoint, worked out from the request's principal.

Without an authorizer every route is open to whoever reaches the router, and `resolveCheckpoint` records whatever `decided_by` the caller sends. That's fine when every caller is trusted equally. It isn't anywhere else, so treat the module without an authorizer as single-trust only.

A few things to know before you call them:

- List routes currently need `limit` and `offset` in the query string. They're meant to be optional (50 by default, capped at 1000), but the request binding rejects a request without them. The same goes for `limit` and `session_id` on the memory routes.
- Every response carries one JSON body. A `200` is serialized by Forge from the handler's result; a `201` (or a `410` replay gap) is written by the handler, which then returns nothing for Forge to write.
- Create, update and list handlers don't translate store errors, so a duplicate name on create comes back as `500` rather than `409`. See [Error format](#error-format).


## Agents (9 routes)

### `POST /cortex/v1/agents`

Create an agent configuration.

**Request**

```json
{
  "name": "support-agent",
  "description": "Customer support agent",
  "system_prompt": "You are a helpful support agent.",
  "model": "gpt-4o",
  "tools": ["lookup_order", "create_ticket"],
  "max_steps": 15,
  "max_tokens": 4096,
  "temperature": 0.7,
  "reasoning_loop": "react",
  "persona_ref": "helpful-agent",
  "inline_skills": ["customer-support"],
  "inline_traits": ["empathy"],
  "inline_behaviors": ["auto-escalate"],
  "guardrails": {},
  "metadata": {}
}
```

**Response** `201 Created` with the agent object and its generated `id` (for example `agt_01h455...`). `name` is required.

---

### `GET /cortex/v1/agents`

List the agents in the caller's scope (and the scopes beneath it).

**Query parameters**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `limit` | int | 50 | Max results, capped at 1000 |
| `offset` | int | 0 | Pagination offset |

**Response** `200 OK` with `{"items": [...]}`, a list of agent objects.

---

### `GET /cortex/v1/agents/:name`

Get an agent by name.

**Response** `200 OK` with the agent object.

**Error** `404 Not Found` if agent does not exist.

---

### `PUT /cortex/v1/agents/:name`

Update an agent configuration. Only provided fields are updated.

**Request**: the same shape as create, with every field optional and the name taken from the path. Empty fields are left alone.

**Response** `200 OK` with the updated agent object.

---

### `DELETE /cortex/v1/agents/:name`

Delete an agent configuration.

**Response** `204 No Content`

---

### `POST /cortex/v1/agents/:name/run`

Execute an agent synchronously. Returns when the run completes.

**Request**

```json
{
  "input": "I want to return order #12345",
  "overrides": {
    "model": "gpt-4o-mini",
    "temperature": 0.2,
    "max_steps": 5
  }
}
```

`input` is required. `overrides` is optional and takes `model`, `temperature`, `max_steps`, `max_tokens`, `reasoning_loop`, `system_prompt`, `persona_ref`, `inline_skills`, `inline_traits`, `inline_behaviors` and `tools` for this run only. There's no session field, so a run over HTTP always lands in the agent's default session for the caller's scope. To run in another session, call `eng.RunAgent` with `RunOverrides.SessionID`.

**Response** `200 OK`

```json
{
  "run_id": "arun_01h455...",
  "state": "completed",
  "output": "I'd be happy to help with your return...",
  "step_count": 3,
  "tokens_used": 1240,
  "duration_ms": 2310
}
```

A run that pauses for an approval or an external tool comes back with `state` set to `paused`.

---

### `POST /cortex/v1/agents/:name/stream`

Execute an agent with Server-Sent Events (SSE) streaming.

**Request**: the same as `/run`.

**Response** `200 OK` with `Content-Type: text/event-stream`. Each engine event is one SSE message, with the event type as the `event:` line and its data as JSON:

```
event: run_started
data: {"agent_id":"agt_01h455...","run_id":"arun_01h455..."}

event: token
data: {"content":"I","index":0}
```

Event types are `run_started`, `step`, `tool_call`, `token`, `checkpoint`, `safety_block`, `suspended`, `done` and `error`.

---

### `POST /cortex/v1/agents/:name/preview-prompt`

Assemble an agent's system prompt without running it, so you can see what its persona identity, skills, traits and the prompt overlays for the caller's scope actually produce.

**Response** `200 OK` with `{"prompt": "..."}`.

---

### `POST /cortex/v1/agents/:name/clone`

Clone an agent into a new, independent copy in the caller's scope. All configuration is copied. The clone gets a fresh `id`, fresh timestamps and no runtime history (runs, sessions and memory stay with the source). It keeps the same `persona_ref`, so the persona is shared, not copied.

**Request**

```json
{
  "new_name": "support-agent-v2"
}
```

`new_name` is optional. If you leave it out, a unique name is generated: `<source>-copy`, then `<source>-copy-2`, `<source>-copy-3` and so on, until one is free.

**Response** `201 Created` with the new agent object.

**Errors**: `404 Not Found` if the source agent doesn't exist, `409 Conflict` if `new_name` is already taken.

## Runs (3 routes)

### `GET /cortex/v1/runs`

List the runs in the caller's scope. There's no filter by agent here; use `eng.ListRuns` with `AgentID` for that.

**Query parameters**

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `limit` | int | 50 | Max results, capped at 1000 |

**Response** `200 OK` with `{"items": [...]}`, a list of run objects.

---

### `GET /cortex/v1/runs/:id`

Get a specific run by ID.

**Response** `200 OK`

```json
{
  "id": "arun_01h455...",
  "agent_id": "agt_01h455...",
  "session_id": "ses_01h455...",
  "scope": {
    "levels": [
      { "key": "workspace", "value": "acme-corp" },
      { "key": "project", "value": "support-bot" }
    ]
  },
  "state": "completed",
  "input": "I want to return order #12345",
  "output": "I'd be happy to help...",
  "error": "",
  "step_count": 3,
  "tokens_used": 1240,
  "started_at": "2024-01-15T10:30:00Z",
  "completed_at": "2024-01-15T10:30:05Z",
  "persona_ref": "helpful-agent",
  "metadata": {}
}
```

`tenant_id` no longer serializes. As of v1.7.0 a run carries `scope`, a
host-defined ordered hierarchy, instead of a single tenant string. See
[Multi-tenancy](/docs/concepts/multi-tenancy).

---

### `POST /cortex/v1/runs/:id/cancel`

Cancel a run that is still running or paused. Sets state to `cancelled`.

A paused run is claimed before it's written, the same way a resume claims it, so
a cancel arriving while somebody is already resuming or deciding that run loses
and comes back `409`. The cancel that wins drops the run's suspension and
resolves whatever checkpoint the pause opened. A run that already finished is
`400`.

**Response** `204 No Content`

## Checkpoints (2 routes)

### `GET /cortex/v1/checkpoints`

List pending checkpoints (runs paused for human approval).

**Query parameters**: `limit`, `offset`.

**Response** `200 OK` with `{"items": [...]}`, a list of checkpoint objects.

---

### `POST /cortex/v1/checkpoints/:id/resolve`

Resolve a checkpoint.

**Request**

```json
{
  "decision": "approved",
  "decided_by": "admin@acme.com",
  "reason": "checked the ticket, it is the right cluster"
}
```

`reason` is optional. On a rejection it lands on the run's `error` field, so
whoever finds the failed run later reads why a person stopped it. An approval
resumes the run synchronously, so this request stays open for as long as the
rest of the run takes.

`decision` is `approved` or `rejected`; anything else is a `400`.

`decided_by` is caller-asserted. With an authorizer installed it's ignored, and the checkpoint records the name `DecidedBy` returns for the request's principal. Without one, the body's value is what gets recorded. The decider's principal is stored on the checkpoint either way but never comes back in a response.

**Response** `204 No Content`

### `GET /cortex/v1/agents/:name/sessions/count`

### `GET /cortex/v1/agents/:name/sessions/:id`

Read one session.

Update a session's `title` or `metadata`.

### `DELETE /cortex/v1/agents/:name/sessions/:id`

Delete a session and the messages in it.

## Configuration (2 routes)

### `GET /cortex/v1/config`

Read the engine's current defaults. `cortex.Config` has no JSON tags, so the fields come back with their Go names, and `ShutdownTimeout` is in nanoseconds:

```json
{
  "DefaultModel": "smart",
  "DefaultMaxSteps": 25,
  "DefaultMaxTokens": 4096,
  "DefaultTemperature": 0.7,
  "DefaultReasoningLoop": "react",
  "ShutdownTimeout": 30000000000,
  "RunConcurrency": 0
}
```

### `PUT /cortex/v1/config`

Change the engine's defaults at runtime. The body takes `default_model`, `default_max_steps`, `default_max_tokens`, `default_temperature` and `default_reasoning_loop`, and zero values are ignored. The change is in memory only and is lost on restart.

**Response** `200 OK` with the updated configuration, in the same shape as `GET`.

## Tools (2 routes)

### `GET /cortex/v1/tools`

The engine's tool catalog, in dispatch order: builtins, then tools registered with `engine.WithTool` (or `tool.Register`), then external tools from `engine.WithExternalTool`. A name is listed once.

**Response** `200 OK`

```json
{
  "items": [
    {"name": "lookup_order", "description": "Looks up an order by id.", "kind": "registered", "retry_safe": true},
    {"name": "deploy", "description": "Deploys a service.", "kind": "external", "retry_safe": false}
  ]
}
```

`kind` is `builtin`, `registered` or `external`. `retry_safe` says whether the tool may run again after a crash. This is the whole catalog, not what one agent sees; for that, call `eng.VisibleTools(ctx, agentID)` in Go.

---

### `GET /cortex/v1/tools/:name/schema`

The JSON Schema of the named tool's parameters, exactly as the engine hands it to a model.

**Response** `200 OK` with the schema object, or `404 Not Found` for a name the engine doesn't know.

## Orchestrations (8 routes)

Multi-agent orchestration. A stored orchestration config names a strategy and its participant agents, and running it coordinates those agents over a shared blackboard. See the [Orchestration guide](/docs/execution/orchestration) for concepts.

### `POST /cortex/v1/orchestrations`

Create an orchestration config.

**Request**

```json
{
  "name": "should-we-ship",
  "description": "Ship-decision debate",
  "strategy": "debate",
  "participants": [
    {"agent_name": "optimist", "role": "debater"},
    {"agent_name": "skeptic", "role": "debater"},
    {"agent_name": "referee", "role": "judge"}
  ],
  "settings": {"rounds": 2, "judge": "referee"},
  "metadata": {}
}
```

`strategy` is one of `sequential`, `parallel`, `router`, `hierarchical`, `debate`. `settings` fields are strategy-specific (`max_concurrency`, `rounds`, `manager`, `judge`, `aggregator`, `router_agent`, `router_rules`, `model`), and each strategy reads only what it needs.

**Response** `201 Created` with the orchestration object and its generated `id` (for example `orchcfg_01h455...`).

**Errors**: `400 Bad Request` if `name` is missing, `strategy` is unknown or `participants` is empty.

---

### `GET /cortex/v1/orchestrations`

List orchestration configs.

**Query parameters**: `limit`, `offset`.

**Response** `200 OK` with `{"items": [...]}`, a list of orchestration objects.

---

### `GET /cortex/v1/orchestrations/:name`

Get an orchestration config by name.

**Response** `200 OK` with the orchestration object. `404 Not Found` if it doesn't exist.

---

### `PUT /cortex/v1/orchestrations/:name`

Update an orchestration config. Only provided fields are updated.

**Response** `200 OK` with the updated orchestration object.

---

### `DELETE /cortex/v1/orchestrations/:name`

Delete an orchestration config.

**Response** `204 No Content`

---

### `POST /cortex/v1/orchestrations/:name/run`

Run a stored orchestration. Executes the strategy across its participant agents and persists an orchestration run.

**Request**

```json
{
  "input": "Should we ship the feature this week?"
}
```

**Response** `200 OK`

```json

  "run_id": "orch_01h455...",

  "output": "...the judge's verdict...",

```

A run that executes but whose strategy fails still returns `200 OK` with `"status": "failed"` (it is not an HTTP error). `404 Not Found` is returned only when the orchestration config does not exist.

### `POST /cortex/v1/agents/:name/messages`

Send an agent a message. This is how a person answers an agent that asked something: set `in_reply_to` to the waiting ask's reply-with token and the run behind it resumes.

**Request**

```json

  "ontology": ""
}
```

`from` and `content` are required, and `performative` defaults to `inform`.

**Response** `201 Created` with the send result.

## Error format

Errors come back as JSON, but the shape depends on where the error came from. A `404`, `409`, `412` or handler-level `400` looks like this:

```json
{
  "code": 404,
  "error": "cortex: agent not found"
}
```

A request that fails binding (a missing required query parameter, say) is a `400` in the same shape, with an `"invalid request: ..."` message. An error the handler doesn't translate reaches Forge's default handling and comes back as a `500`:

```json
{
  "code": "INTERNAL_SERVER_ERROR",
  "message": "create agent: cortex/sqlite: create agent: cortex: resource already exists"
}
```

| HTTP status | Cause |
|-------------|-------|
| `400` | Missing or invalid input: a required field, an unparseable ID, an unknown strategy or checkpoint decision, a missing query parameter |
| `404` | The entity doesn't exist in the caller's scope (a row in another scope looks the same) |
| `409` | A name that's already taken, on clone; a run someone else is already resuming, on cancel |
| `412` | The request has no scope, on routes that map store errors |
| `500` | Anything else, including a duplicate name on create and a missing scope on create, update and list routes |
