title: Go Packages

Most packages live in the root module, `github.com/xraph/cortex`. The REST handlers (`api`), the Forge extension (`extension`), the Sentinel adapter (`sentinel`), the Fabriq integration (`integrations/fabriq`) and the remote A2A support (`a2aremote`) are separate modules you add on their own. This page lists the main exports; [pkg.go.dev](https://pkg.go.dev/github.com/xraph/cortex) has everything.

## Core packages

### `github.com/xraph/cortex`

Root package. Context helpers, sentinel errors, configuration and shared types.

| Export | Description |
|--------|-------------|
| `WithScope(ctx, scope)` | Attach a host-defined `Scope` to the context (at most three levels, no empty keys or values) |
| `ScopeFromContext(ctx)` | Read the `Scope` back (zero value if absent) |
| `Scope`, `Level` | Host-defined scope hierarchy, with `IsZero`, `Covers`, `Get` and `Canonical`; `ParseCanonical` reverses `Canonical` |
| `WithPrincipal(ctx, p)`, `PrincipalFromContext(ctx)` | Carry your caller identity through to the `ToolAuthorizer` |
| `ToolAuthorizer`, `Subject`, `Invocation`, `ErrRequiresApproval` | Tool visibility and dispatch decisions; see [Tool Authorization](/docs/concepts/authorization) |
| `Config`, `DefaultConfig()` | Engine defaults |
| `Entity`, `NewEntity()` | Base entity with `CreatedAt` and `UpdatedAt` |
| `ErrNoStore`, `ErrNoScope`, `ErrAgentNotFound`, `ErrAlreadyExists`, `ErrNotSuspended`, ... | Sentinel errors; see [Error Handling](/docs/concepts/errors) |
| `Rescoper`, `MigrateOption`, `WithRescoper(r)`, `ApplyMigrateOptions(...)`, `ValidateRescopedScope(s)`, `ErrNoRescoper` | Legacy-row migration; see the [rescope guide](/docs/guides/v1.8-rescope) |

### `github.com/xraph/cortex/engine`

The central coordinator.

| Export | Description |
|--------|-------------|
| `New(...Option) (*Engine, error)` | Create an engine |
| `Engine.Start(ctx)`, `Engine.Stop(ctx)` | Start and stop the suspension sweeper and the message bus; `Stop` emits `OnShutdown` |
| `Engine.Health(ctx)` | Ping the store |
| `Engine.Store()`, `Extensions()`, `Config()`, `UpdateConfig(cfg)`, `LLM()`, `Safety()`, `Knowledge()`, `A2A()` | Accessors |
| `Engine.RunAgent(ctx, name, input, overrides)` | Run an agent and wait for the `*run.Run` |
| `Engine.StreamAgent(ctx, name, input, overrides, events)` | Run an agent and send `StreamEvent`s on a channel, which it closes |
| `Engine.Resume`, `ResumeStream`, `CancelRun` | Continue or cancel a suspended run |
| `Engine.BuildSystemPrompt(ctx, ag, overrides)` | The assembled system prompt for an agent |
| `Engine.CreateAgent`, `GetAgent`, `GetAgentByName`, `UpdateAgent`, `DeleteAgent`, `ListAgents`, `CountAgents`, `CloneAgent` | Agents |
| `Engine.CreateSkill`, `GetSkillByName`, `ListSkills`, ... (and the same for traits, behaviors and personas, plus `ClonePersona`) | Human model CRUD |
| `Engine.GetRun`, `ListRuns`, `CountRuns`, `ListSteps`, `ListToolCalls` | Run history |
| `Engine.LoadConversation`, `ClearConversation` | Conversation memory, per session |
| `Engine.ListPendingCheckpoints`, `CountPendingCheckpoints`, `GetCheckpoint`, `ResolveCheckpoint` | Checkpoints |
| `Engine.CreateOrchestration`, `RunOrchestration(ctx, name, input)`, `ListOrchestrationRuns`, ... | Orchestration |
| `Engine.SendMessage`, `AgentInbox`, `ListConversations`, `GetConversation`, `ListMessages` | Agent messaging |
| `Engine.VisibleTools(ctx, agentID)` | The tools an agent would see |
| `RunOverrides`, `ResumeInput`, `ToolResult`, `StreamEvent`, `ToolHandler` | Run inputs and outputs |
| `WithStore`, `WithLLM`, `WithConfig`, `WithTool`, `WithExternalTool`, `WithToolAuthorizer`, `WithSafety`, `WithKnowledge`, `WithA2A`, `WithExtension`, `WithLogger`, `WithSuspensionTTL`, `WithSuspensionSweepInterval`, `WithSuspensionSweepLimit` | Engine options; see [Configuration](/docs/concepts/configuration) |

## Domain packages

### `github.com/xraph/cortex/agent`

Agent configuration and store interface.

```go
type Config struct {
    cortex.Entity
    ID                                         id.AgentID
    Name, Description, SystemPrompt, Model     string
    Scope                                      cortex.Scope
    Tools                                      []string // restricts the tools the model sees
    MaxSteps, MaxTokens                        int
    Temperature                                float64
    ReasoningLoop                              string
    Guardrails, Metadata                       map[string]any
    Enabled                                    bool
    PersonaRef                                 string
    InlineSkills, InlineTraits, InlineBehaviors []string
    Sections                                   []prompt.Section // wins over SystemPrompt
}

func (c *Config) PromptSections() []prompt.Section
func (c *Config) SyncSystemPrompt()
func (c *Config) HasPersona() bool
func CloneConfig(src *Config, newID id.AgentID, newName string) (*Config, error)

const RoleSectionID = "role"

type Store interface { // 7 methods
    Create, Get, GetByName, Update, Delete, List, CountAgents
}
```

A non-empty `Sections` derives `SystemPrompt` and overwrites it, and an empty `Sections` with a non-empty `SystemPrompt` lowers into one section with id `role`. See [Prompt Composition](/docs/concepts/prompt-composition).

### `github.com/xraph/cortex/prompt`

Prompt sections, the overlay that patches them, and the overlay store.

```go
type Section struct {
    ID, Body string
    Source   Source   // host, persona, skill, trait, knowledge
    Title    string   // prefixed to Body when non-empty
    Order    int      // low first, ties broken by ID
    Locked   bool     // refuses replace, still accepts append
}

type Patch struct {
    ID, Body string
    Mode     PatchMode // replace (default), append, and nothing else
}

func ApplyOverlay(sections []Section, patches []Patch) ([]Section, []Patch)
func Assemble(sections []Section) string

const OrderRole, OrderPersona, OrderSkill, OrderKnowledge, OrderTrait = 1000, 2000, 3000, 4000, 5000

type Overlay struct {
    cortex.Entity
    ID                       id.OverlayID
    AgentID                  id.AgentID
    Scope                    cortex.Scope
    Patches                  []Patch
    ToolsAdded, ToolsRemoved []string
    Model                    string
    Temperature              *float64
    MaxTokens                *int
}

type Store interface { // 7 methods
    CreateOverlay, GetOverlay, GetOverlayForAgent, GetOverlayForAgentAt,
    UpdateOverlay, DeleteOverlay, ListOverlays
}
```

`ApplyOverlay` returns the patches it declined as its second value. A `Locked` section takes an append and nothing else, so a replace is declined and so is any `Mode` outside the two constants. See [Prompt Composition](/docs/concepts/prompt-composition).

### `github.com/xraph/cortex/cognitive`, `communication`, `perception`

Value objects embedded in a persona. They're stored and returned, but the engine doesn't apply them yet.

```go

}
type Phase struct {
    Strategy   Strategy            // analytical, creative, methodical, reactive, reflective, collaborative
    MaxSteps   int

}

// communication
type Style struct {
    Tone, PreferredFormat                string
    Formality, Verbosity, TechnicalLevel float64
    EmojiUsage, AdaptToUser              bool
}

// perception
type Model struct {
    AttentionFilters                 []AttentionFilter
    ContextWindow, DetailOrientation float64
}
type AttentionFilter struct {
    Name               string
    Keywords, Patterns []string
    Prompt             string
}
```

### `github.com/xraph/cortex/a2a`

The in-process agent-to-agent bus: FIPA-ACL envelopes, conversations, deliveries, pending asks, and Contract Net helpers (`ContractNet`, `CollectTender`). Turn it on with `engine.WithA2A(a2a.Options{...})`. Its `Store` has 20 methods. See [Agent Messaging](/docs/execution/messaging).

## Adapters

| Package | What it is |
|---------|------------|
| `llm` | `Client` interface (`Complete`, `CompleteStream`), with `Request`, `Response`, `Tool`, `ToolCall` and `Message` |
| `llm/nexus` | `New(*nexus.Gateway)` adapts a Nexus gateway; `EngineOption(container)` finds one in a vessel container |
| `safety` | `Scanner` interface (`ScanInput`, `ScanOutput`) |
| `safety/shield` | `New(*shield engine)` adapts Shield; `EngineOption(container)` |
| `knowledge` | `Provider` interface (`Retrieve`, `ListCollections`) |
| `knowledge/weave` | `New(*weave engine)` adapts Weave; `EngineOption(container)` |

Each `EngineOption(container)` returns a no-op option when its service isn't in the container, which is how the Forge extension wires them all unconditionally.

## Identity package

### `github.com/xraph/cortex/id`

TypeID-based identifiers (UUIDv7, K-sortable). Every entity ID type is an alias of one struct.

```go
type ID struct { /* wraps a TypeID */ }

// Aliases: AgentID, AgentRunID, ToolID, ToolCallID, StepID, MemoryID,
// CheckpointID, OrchestrationID, OrchestrationConfigID, SkillID, TraitID,
// BehaviorID, PersonaID, SessionID, SuspensionID, OverlayID, MessageID,
// ConversationID, DeliveryID, AnyID = ID

// Constructors: New(prefix), NewAgentID(), NewSkillID(), ...
// Parsers: Parse(s), ParseWithPrefix(s, prefix), ParseAgentID(s), MustParse(s), ...

// Prefixes: agt, arun, tool, tcall, astp, mem, acp, orch, orchcfg, skl, trt,
// bhv, prs, ses, sus, ovl, msg, conv, dlv
```

See [Identity](/docs/concepts/identity).

### `github.com/xraph/cortex/store/postgres`, `store/sqlite`, `store/mongo`

The three backends, all on Grove.

```go
func New(db *grove.DB) *Store
```

PostgreSQL and SQLite register their migrations in Go and need Grove's `pgmigrate` or `sqlitemigrate` executor imported; MongoDB only creates indexes.

### `github.com/xraph/cortex/sentinel`

Evaluation through [Sentinel](https://github.com/xraph/sentinel): `EngineOption(container, ...Option)`, `New(*sentinel engine, ...Option)` for the plugin, and `NewAgentClient(eng)`.

### `github.com/xraph/cortex/integrations/fabriq`

Package `fabriqbrain`: Fabriq as a knowledge provider, extra tools and a learning-loop plugin. See [Fabriq Brain](/docs/integrations/fabriq).

### `github.com/xraph/cortex/a2aremote`

Agent2Agent over JSON-RPC, REST and SSE, with gRPC in `a2aremote/grpcbind`. Not tagged yet. See [Remote Agents](/docs/execution/remote-messaging).
