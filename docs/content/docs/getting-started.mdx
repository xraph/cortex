## Prerequisites

- Go 1.26 or later
- A Go module (`go mod init`)

You don't need a model API key to follow along. An engine without an LLM client runs agents in an echo mode, which is enough to see the whole flow work. The last step plugs in a real model.

## Install

```bash
go get github.com/xraph/cortex@latest
go get github.com/xraph/grove/drivers/sqlitedriver@latest
```

This guide uses SQLite so there's nothing to start. PostgreSQL and MongoDB work the same way with their own store package (see [Stores](/docs/stores/postgres)).

## Step 1: Create the store and the engine

The engine is the central coordinator. It needs a store for persistence, and the store needs its tables:

```go
package main

import (
    "context"
    "log"

    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/sqlitedriver"
    _ "github.com/xraph/grove/drivers/sqlitedriver/sqlitemigrate"

    "github.com/xraph/cortex/engine"
    sqlitestore "github.com/xraph/cortex/store/sqlite"
)

func main() {
    ctx := context.Background()

    drv := sqlitedriver.New()
    if err := drv.Open(ctx, "cortex.db"); err != nil {
        log.Fatal(err)
    }
    db, err := grove.Open(drv)
    if err != nil {
        log.Fatal(err)
    }
    st := sqlitestore.New(db)

    // Create the tables.
    if err := st.Migrate(ctx); err != nil {
        log.Fatal(err)
    }

    eng, err := engine.New(
        engine.WithStore(st),
    )
    if err != nil {
        log.Fatal(err)
    }
    if err := eng.Start(ctx); err != nil {
        log.Fatal(err)
    }
    defer eng.Stop(ctx)
}
```

The blank `sqlitemigrate` import registers Grove's migration executor for SQLite. Leave it out and `Migrate` fails with "no executor registered for driver". For PostgreSQL the import is `github.com/xraph/grove/drivers/pgdriver/pgmigrate`. The MongoDB store only creates indexes and needs no executor.

## Step 2: Set up a scoped context

Cortex has no built-in notion of tenant, workspace or app. You define your own scope levels and attach them to the context. An app dimension is just another level:

```go
import "github.com/xraph/cortex"

ctx = cortex.WithScope(ctx, cortex.Scope{
    Levels: []cortex.Level{
        {Key: "tenant", Value: "tenant-1"},
        {Key: "app", Value: "myapp"},
    },
})
```

Every store call needs a scope. A zero scope fails with `cortex.ErrNoScope` instead of silently matching everything, and everything you create below is stored under these levels. See [Multi-Tenancy](/docs/concepts/multi-tenancy) for how lists match by prefix.

## Step 3: Create a skill

A skill bundles a prompt fragment with the tools and knowledge that go with it:

```go
import (
    "github.com/xraph/cortex/id"
    "github.com/xraph/cortex/skill"
)

codeReview := &skill.Skill{
    ID:          id.NewSkillID(),
    Name:        "code-review",
    Description: "Review pull requests for bugs, style, and security issues",
    Tools: []skill.ToolBinding{
        {ToolName: "read_file", Mastery: skill.ProficiencyExpert},
        {ToolName: "search_code", Mastery: skill.ProficiencyProficient},
    },
    SystemPromptFragment: "You are an expert code reviewer. Focus on correctness, security, and maintainability.",
    DefaultProficiency:   skill.ProficiencyProficient,
}
if err := eng.CreateSkill(ctx, codeReview); err != nil {
    log.Fatal(err)
}
```

Set the ID yourself with the `id` package. The stores don't generate one for you.

When an agent lists this skill, the engine adds the `SystemPromptFragment` to its system prompt and pulls in any `Knowledge` references through the knowledge provider. The tool bindings are stored with the skill, but the engine doesn't use them to pick tools yet. An agent's `Tools` list decides which tools the model sees.

## Step 4: Create a trait

A trait is a personality dimension. Its influences say how it changes the agent:

```go
import "github.com/xraph/cortex/trait"

thoroughness := &trait.Trait{
    ID:       id.NewTraitID(),
    Name:     "thoroughness",
    Category: trait.CategoryWorkstyle,
    Dimensions: []trait.Dimension{
        {Name: "depth", LowLabel: "surface-level", HighLabel: "exhaustive", Value: 0.85},
    },
    Influences: []trait.Influence{
        {Target: trait.TargetPromptInjection, Value: "Check every changed line. Never approve on a skim."},
    },
}
if err := eng.CreateTrait(ctx, thoroughness); err != nil {
    log.Fatal(err)
}
```

Only `prompt_injection` influences with a string value reach the prompt today. The other targets (`temperature`, `max_steps`, `tool_selection`, `response_style`) are stored but not applied.

## Step 5: Create a persona

A persona gives the agent an identity and groups skills, traits, behaviors and styles under one name:

```go
import (
    "github.com/xraph/cortex/communication"
    "github.com/xraph/cortex/persona"
)

seniorEng := &persona.Persona{
    ID:       id.NewPersonaID(),
    Name:     "senior-engineer",
    Identity: "A senior software engineer with 10+ years of experience",
    Skills: []persona.SkillAssignment{
        {SkillName: "code-review", Proficiency: skill.ProficiencyExpert},
    },
    Traits: []persona.TraitAssignment{
        {TraitName: "thoroughness", DimensionValues: map[string]float64{"depth": 0.9}},
    },
    CommunicationStyle: communication.Style{
        Tone:           "professional",
        Formality:      0.7,
        Verbosity:      0.5,
        TechnicalLevel: 0.9,
    },
}
if err := eng.CreatePersona(ctx, seniorEng); err != nil {
    log.Fatal(err)
}
```

At run time the engine uses the persona's `Identity`. Its skill and trait assignments, behaviors and styles are stored and served by the API, but a run doesn't read them, so list the skills and traits you want on the agent itself (next step).

## Step 6: Create an agent

An agent points at a persona and lists the skills and traits it uses:

```go
import "github.com/xraph/cortex/agent"

agentCfg := &agent.Config{
    ID:           id.NewAgentID(),
    Name:         "reviewer-bot",
    SystemPrompt: "You review pull requests and reply with a short list of findings.",
    PersonaRef:   "senior-engineer",
    InlineSkills: []string{"code-review"},
    InlineTraits: []string{"thoroughness"},
    Model:        "gpt-4o",
    MaxSteps:     25,
}
if err := eng.CreateAgent(ctx, agentCfg); err != nil {
    log.Fatal(err)
}
```

You can see what the model will get before you run anything:

```go
prompt, err := eng.BuildSystemPrompt(ctx, agentCfg, nil)
if err != nil {
    log.Fatal(err)
}
fmt.Println(prompt)
```

That prints the system prompt, then `## Identity`, `## Skill: code-review` and `## Trait: thoroughness` sections built from the records above.

## Step 7: Run the agent

```go
import "github.com/xraph/cortex/run"

r, err := eng.RunAgent(ctx, "reviewer-bot", "Review this diff: ...", nil)
if err != nil {
    log.Fatal(err)
}
fmt.Println(r.State, r.Output) // completed Echo: Review this diff: ...

// Every run is stored with its steps and tool calls.
steps, _ := eng.ListSteps(ctx, r.ID)
runs, _ := eng.ListRuns(ctx, &run.ListFilter{AgentID: agentCfg.ID.String()})
```

Without an LLM client the engine echoes the input back. To run against a real model, give the engine an `llm.Client`. The bundled adapter wraps a [Nexus](https://github.com/xraph/nexus) gateway:

```bash
go get github.com/xraph/nexus@latest github.com/xraph/nexus/providers/openai@latest
```

```go
import (
    "os"

    "github.com/xraph/nexus"
    "github.com/xraph/nexus/providers/openai"

    nexusllm "github.com/xraph/cortex/llm/nexus"
)

gw := nexus.New(nexus.WithProvider(openai.New(os.Getenv("OPENAI_API_KEY"))))
if err := gw.Initialize(ctx); err != nil {
    log.Fatal(err)
}
defer gw.Shutdown(ctx)

eng, err := engine.New(
    engine.WithStore(st),
    engine.WithLLM(nexusllm.New(gw)),
)
```

Tools the model can call are registered with `engine.WithTool(def, handler)`. The [README quick start](https://github.com/xraph/cortex#quick-start) shows one end to end.

If you run Cortex inside a Forge app, the REST handlers in the `api` module expose the same operations over HTTP once you mount them. See [Forge Extension](/docs/guides/forge-extension).
