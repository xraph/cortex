---
title: Behaviors
description: Define what an agent does habitually, as trigger and action patterns.
---

A behavior is a trigger and action pattern, the habits and reflexes that turn skills and traits into contextual responses. The idea is that when a trigger condition is met, the behavior fires its actions.

That part isn't implemented yet. The engine stores behaviors, scopes them, and serves them through its CRUD methods and the REST API, and you can attach them to personas and agents. But no run evaluates a trigger or performs an action, whether the behavior sits in a persona's `Behaviors` or an agent's `InlineBehaviors`, and the `OnBehaviorTriggered` plugin hook never fires. The tables below describe what each type is meant for.

## Structure

```go
type Behavior struct {
    cortex.Entity
    ID            id.BehaviorID
    Name          string
    Description   string
    Scope         cortex.Scope // set from the context on create
    Triggers      []Trigger
    Actions       []Action
    Priority      int
    RequiresSkill string
    RequiresTrait string
    Metadata      map[string]any
}
```

## Triggers

Triggers say when a behavior should activate:

```go
type Trigger struct {
    Type    TriggerType
    Pattern string       // optional pattern for matching
}
```

### Trigger types

| Type | Description |
|------|-------------|
| `on_input` | Fires when user input matches a pattern |
| `on_tool_result` | Fires when a tool returns a specific result |
| `on_error` | Fires when an error occurs |
| `on_step_count` | Fires when the step count reaches a threshold |
| `on_context` | Fires based on conversation context |
| `always` | Fires on every step |

## Actions

Actions say what should happen when a behavior triggers:

```go
type Action struct {
    Type   ActionType
    Target string      // action-specific target
    Value  any         // action-specific value
}
```

### Action types

| Type | Description |
|------|-------------|
| `inject_prompt` | Inject text into the system prompt |
| `prefer_skill` | Increase preference for a specific skill |
| `require_tool` | Force usage of a specific tool |
| `modify_param` | Modify a runtime parameter |
| `switch_cognitive` | Switch to a different cognitive phase |
| `add_guardrail` | Add a runtime guardrail check |

## Priority

`Priority` is an integer meant to order behaviors that trigger at the same time. Nothing reads it yet, so the code doesn't define which direction wins.

```go
behavior := &behavior.Behavior{
    Priority: 10,
}
```

## Skill and trait requirements

A behavior can name a skill or trait that has to be active for it to apply (stored, not checked yet):

```go
behavior := &behavior.Behavior{
    Name:          "verify-before-suggest",
    RequiresSkill: "code-review",
    RequiresTrait: "thoroughness",
    Triggers: []behavior.Trigger{
        {Type: behavior.TriggerAlways},
    },
    Actions: []behavior.Action{
        {Type: behavior.ActionInjectPrompt, Value: "Always verify your analysis before suggesting changes."},
    },
}
```

## Store interface

```go
type Store interface {
    CreateBehavior(ctx context.Context, behavior *Behavior) error
    GetBehavior(ctx context.Context, behaviorID id.BehaviorID) (*Behavior, error)
    GetBehaviorByName(ctx context.Context, name string) (*Behavior, error)
    UpdateBehavior(ctx context.Context, behavior *Behavior) error
    DeleteBehavior(ctx context.Context, behaviorID id.BehaviorID) error
    ListBehaviors(ctx context.Context, filter *ListFilter) ([]*Behavior, error)
    CountBehaviors(ctx context.Context, filter *ListFilter) (int64, error)
}
```

## API routes

These exist when you mount the `api` module through `extension.WithRoutes` (paths shown with the default `/cortex` base path):

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/cortex/v1/behaviors` | Create a behavior |
| `GET` | `/cortex/v1/behaviors` | List behaviors |
| `GET` | `/cortex/v1/behaviors/:name` | Get a behavior by name |
| `PUT` | `/cortex/v1/behaviors/:name` | Update a behavior |
| `DELETE` | `/cortex/v1/behaviors/:name` | Delete a behavior |
