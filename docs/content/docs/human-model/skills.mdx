---
title: Skills
description: Define what an agent can do, with a prompt fragment, tools and knowledge sources.
---

A skill represents a coherent capability an agent can have. Think of it as professional training: it bundles related tools, knowledge sources and prompt guidance into a named, reusable entity.

An agent uses a skill when it names it in `InlineSkills`. A skill that's only assigned to the agent's persona isn't loaded into a run.

## Structure

```go
type Skill struct {
    cortex.Entity
    ID                   id.SkillID
    Name                 string
    Description          string
    Scope                cortex.Scope // set from the context on create
    Tools                []ToolBinding
    Knowledge            []KnowledgeRef
    SystemPromptFragment string
    Dependencies         []string
    DefaultProficiency   Proficiency
    Metadata             map[string]any
}
```

## Tool bindings

Each tool binding associates a tool with a mastery level and contextual guidance:

```go
type ToolBinding struct {
    ToolName   string      // name of the tool
    Mastery    Proficiency // how well the agent uses this tool
    Guidance   string      // when/how to use it
    PreferWhen string      // conditions that favor this tool
}
```

Tool bindings are stored with the skill but the engine doesn't read them yet. They don't register a tool, grant one, or add the guidance to the prompt. The tools a model can call come from `engine.WithTool` registrations, filtered by the agent's `Tools` list and your `ToolAuthorizer`.

## Knowledge references

Knowledge references pull context into the prompt when an agent uses the skill:

```go
type KnowledgeRef struct {
    Source     string // the collection the knowledge provider retrieves from
    InjectMode string // stored, not used yet
    Priority   int    // stored, not used yet
}
```

When the engine has a knowledge provider (`engine.WithKnowledge`, or Weave discovered by the Forge extension), each `Source` is retrieved and added as a `knowledge:<source>` section. A failed or empty retrieval is skipped rather than failing the run. Without a provider, knowledge references do nothing.

## Proficiency levels

Skills use a five-level proficiency system that maps to numeric weights:

| Level | Weight | Description |
|-------|--------|-------------|
| `novice` | 0.2 | Basic awareness, needs guidance |
| `apprentice` | 0.4 | Can use with supervision |
| `competent` | 0.6 | Independent usage (default) |
| `proficient` | 0.8 | Deep understanding, handles edge cases |
| `expert` | 1.0 | Mastery, can teach others |

`Proficiency.Weight()` returns these numbers, and an unknown level weighs 0.6. The engine doesn't use proficiency yet, so a skill's level, a tool binding's `Mastery` and a persona's `SkillAssignment.Proficiency` don't change a run.

## System prompt fragments

Each skill can contribute a fragment to the agent's system prompt:

```go
skill := &skill.Skill{
    Name: "code-review",
    SystemPromptFragment: "You are an expert code reviewer. Focus on correctness, security, and maintainability. Always explain your reasoning.",
}
```

The fragment becomes a section with the id `skill:<name>` and the body `## Skill: <name>` followed by the fragment. When an agent lists several skills in `InlineSkills`, each one gets its own section, in list order. A skill without a fragment adds nothing.

## Dependencies

Skills can declare dependencies on other skills:

```go
skill := &skill.Skill{
    Name:         "security-audit",
    Dependencies: []string{"code-review"},
}
```

Dependencies are stored only. Listing `security-audit` doesn't pull `code-review` into a run, so list both in `InlineSkills`.

## Store interface

```go
type Store interface {
    CreateSkill(ctx context.Context, skill *Skill) error
    GetSkill(ctx context.Context, skillID id.SkillID) (*Skill, error)
    GetSkillByName(ctx context.Context, name string) (*Skill, error)
    UpdateSkill(ctx context.Context, skill *Skill) error
    DeleteSkill(ctx context.Context, skillID id.SkillID) error
    ListSkills(ctx context.Context, filter *ListFilter) ([]*Skill, error)
    CountSkills(ctx context.Context, filter *ListFilter) (int64, error)
}
```

## API routes

These exist when you mount the `api` module through `extension.WithRoutes` (paths shown with the default `/cortex` base path):

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/cortex/v1/skills` | Create a skill |
| `GET` | `/cortex/v1/skills` | List skills |
| `GET` | `/cortex/v1/skills/:name` | Get a skill by name |
| `PUT` | `/cortex/v1/skills/:name` | Update a skill |
| `DELETE` | `/cortex/v1/skills/:name` | Delete a skill |
