---
title: Forge Extension
description: Mount Cortex into a Forge application as an extension, with DI, migrations and optional REST routes.
---

Cortex ships a Forge extension in its own module, `github.com/xraph/cortex/extension`. It builds the engine, provides it through Forge's DI container, runs migrations on start and plugs into Forge's health checks and dashboard. The REST handlers live in another module, `github.com/xraph/cortex/api`, and the extension only mounts them when you ask it to.

## Installation

```bash
go get github.com/xraph/cortex/extension@latest
go get github.com/xraph/cortex/api@latest   # only if you want the REST routes
```

## Registering the extension

```go
package main

import (
    "context"
    "log"
    "os"

    "github.com/xraph/forge"
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    _ "github.com/xraph/grove/drivers/pgdriver/pgmigrate"

    "github.com/xraph/cortex/api"
    "github.com/xraph/cortex/engine"
    cortexext "github.com/xraph/cortex/extension"
    pgstore "github.com/xraph/cortex/store/postgres"
)

func main() {
    ctx := context.Background()

    drv := pgdriver.New()
    if err := drv.Open(ctx, os.Getenv("DATABASE_URL")); err != nil {
        log.Fatal(err)
    }
    db, err := grove.Open(drv)
    if err != nil {
        log.Fatal(err)
    }

    cortexExt := cortexext.New(
        cortexext.WithStore(pgstore.New(db)),
        cortexext.WithRoutes(func(eng *engine.Engine, r forge.Router) cortexext.RouteSet {
            return api.New(eng, r)
        }),
    )

    app := forge.NewApp(forge.AppConfig{
        Name:        "agents",
        HTTPAddress: ":8080",
        Extensions:  []forge.Extension{cortexExt},
    })

    if err := app.Run(); err != nil {
        log.Fatal(err)
    }
}
```

The blank `pgmigrate` import registers Grove's migration executor for PostgreSQL. Without it, the migration the extension runs on start fails with "no executor registered for driver". Use `sqlitedriver/sqlitemigrate` for SQLite. The MongoDB store only creates indexes and needs no executor.

`forge.New(forge.WithExtensions(cortexExt))` and `app.RegisterExtension(cortexExt)` work too, if that's how your app is put together.

## Routes are opt-in

The extension mounts no HTTP routes by itself. `WithRoutes` takes a function that builds a `RouteSet` from the engine and the app's router, and `api.New` is the one Cortex provides. The extension mounts it under `base_path` (default `/cortex`), and every handler in the `api` module sits in a `/v1` group, so you get 59 routes such as `POST /cortex/v1/agents` and `POST /cortex/v1/agents/:name/run`. The [HTTP API reference](/docs/api-reference/http-api) lists them all.

Leave `WithRoutes` out and you still get the engine in the container, migrations, health checks and the dashboard contract. `Routes()` then returns nil and `Handler()` answers 404.

## What the extension does

| Lifecycle event | Behaviour |
|----------------|-----------|
| `Register` | Loads config, resolves a store, adds the Nexus, Shield, Weave and Sentinel engine options, builds the engine, provides `*engine.Engine` in the DI container, and mounts the route set if you passed `WithRoutes` (unless routes are disabled) |
| `Start` | Runs `store.Migrate(ctx)` (unless disabled), then calls `engine.Start(ctx)` |
| `Stop` | Calls `engine.Stop(ctx)`, which stops the sweeper and emits `OnShutdown` to all plugins |
| `Health` | Calls `store.Ping(ctx)`. With no store it reports "cortex: no store configured" |

The Nexus, Shield, Weave and Sentinel options look for their service in the container. Each one does nothing when its service isn't registered, so a plain app with no gateway runs agents in echo mode. Put a `*nexus.Gateway` in the container (for example with the Nexus Forge extension) and agents talk to real models without any Cortex config. The lookup happens once, in `Register`, so the gateway has to be there by the time Cortex registers. A gateway found this way replaces an LLM client you passed with `WithEngineOption(engine.WithLLM(...))`.

## Extension options

| Option | Type | Description |
|--------|------|-------------|
| `WithStore(s)` | `store.Store` | Use this store. A Grove database found in the container takes precedence (see below) |
| `WithGroveDatabase(name)` | `string` | Resolve the named `*grove.DB` from DI and build the matching store. An empty name uses the default DB |
| `WithRoutes(build)` | `func(*engine.Engine, forge.Router) extension.RouteSet` | Mount a route set, normally `api.New` |
| `WithBasePath(p)` | `string` | URL prefix for the routes. Defaults to `/cortex` |
| `WithDisableRoutes()` | | Skip mounting the route set even when `WithRoutes` is set |
| `WithDisableMigrate()` | | Skip `Migrate` on start |
| `WithExtension(x)` | `plugin.Extension` | Register a Cortex plugin (lifecycle hooks) |
| `WithEngineOption(o)` | `engine.Option` | Pass any engine option through, such as `engine.WithLLM`, `engine.WithTool` or `engine.WithConfig` |
| `WithConfig(c)` | `extension.Config` | Set the whole extension config |
| `WithRequireConfig(b)` | `bool` | Fail `Register` when no `extensions.cortex` or `cortex` config is found |
| `WithDashboard(deps)` | `contract.Deps` | Supply the scope mapping and audit sink for the dashboard contract |

There's no logger option. The extension logs through the Forge app's logger, and the engine keeps its no-op logger unless you pass `WithEngineOption(engine.WithLogger(l))`.

## Extension config struct

```go
type Config struct {
    DisableRoutes        bool          // skip mounting the route set
    DisableMigrate       bool          // skip auto-migration on start
    BasePath             string        // URL prefix for the routes (empty means "/cortex")
    DefaultModel         string        // default: "smart"
    DefaultMaxSteps      int           // default: 25
    DefaultMaxTokens     int           // default: 4096
    DefaultTemperature   float64       // default: 0.7
    DefaultReasoningLoop string        // default: "react"
    ShutdownTimeout      time.Duration // default: 30s
    RunConcurrency       int           // default: 4
    GroveDatabase        string        // name of the grove.DB to resolve from DI
    RequireConfig        bool          // not read from YAML
}
```

The extension reads `DefaultModel`, `DefaultMaxSteps`, `DefaultMaxTokens`, `DefaultTemperature`, `DefaultReasoningLoop`, `ShutdownTimeout` and `RunConcurrency` but doesn't pass them to the engine, so setting them has no effect yet. The engine runs on `cortex.DefaultConfig()`, which happens to have the same values. To change the engine defaults, pass them in code with `WithEngineOption(engine.WithConfig(...))`. `ShutdownTimeout` and `RunConcurrency` aren't used by the engine either.

```go
cortexExt := cortexext.New(
    cortexext.WithEngineOption(engine.WithConfig(cortex.Config{
        DefaultModel:         "gpt-4o",
        DefaultMaxSteps:      50,
        DefaultMaxTokens:     8192,
        DefaultTemperature:   0.7,
        DefaultReasoningLoop: "react",
    })),
)
```

## YAML configuration

The extension reads `extensions.cortex`, and falls back to a top-level `cortex` key:

```yaml
# config.yaml
extensions:
  cortex:
    disable_routes: false
    disable_migrate: false
    base_path: "/cortex"
    grove_database: "cortex"
```

The `default_*`, `shutdown_timeout` and `run_concurrency` keys are accepted too, with the caveat above.

### Config resolution order

1. YAML values are loaded first (from `extensions.cortex` or `cortex`).
2. Programmatic values (`WithConfig`, `WithBasePath` and so on) fill any field the YAML left empty. `WithDisableRoutes` and `WithDisableMigrate` always win when set.
3. Remaining zero fields get the defaults from `extension.DefaultConfig()`.

### Requiring configuration

To make Cortex fail when no YAML config is found:

```go
cortexExt := cortexext.New(
    cortexext.WithRequireConfig(true),
)
```

## Disabling auto-migration

If you run migrations separately, turn off the one on start:

```go
cortexExt := cortexext.New(
    cortexext.WithStore(store),
    cortexext.WithDisableMigrate(),
)
```

## Accessing the engine from other extensions

After Forge calls `Register`, `cortexExt.Engine()` returns the engine:

```go
eng := cortexExt.Engine()
// Use eng.CreateAgent, eng.RunAgent, etc.
```

The engine is also in Forge's DI container, so another extension can resolve it by type:

```go
import "github.com/xraph/cortex/engine"

// Inside another extension's Register (or Start):
eng, err := forge.Inject[*engine.Engine](app.Container())
if err != nil {
    return err
}
```

`vessel.Inject[*engine.Engine]` does the same. Register Cortex before the extensions that need it, or declare it as a dependency.

## Scope middleware

Cortex has no built-in notion of tenant, workspace or organization. Your app attaches a scope to every request before it reaches Cortex, typically in middleware that reads the JWT or API key. Every scope-guarded operation rejects a zero scope with `cortex.ErrNoScope`, so the REST routes don't work without it.

`forge.Router.Use` takes Forge's own `Middleware` type (`func(next forge.Handler) forge.Handler`, built on `forge.Context`), not a plain `net/http` middleware. You can write an ordinary `net/http` middleware anyway, type it as `forge.PureMiddleware` (`func(http.Handler) http.Handler`), and convert it with `.ToMiddleware()`:

```go
func scopeMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        tenantID := r.Header.Get("X-Tenant-ID")
        appID := r.Header.Get("X-App-ID")
        levels := []cortex.Level{{Key: "tenant", Value: tenantID}}
        if appID != "" {
            levels = append(levels, cortex.Level{Key: "app", Value: appID})
        }
        ctx := cortex.WithScope(r.Context(), cortex.Scope{Levels: levels})
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

app.Router().Use(forge.PureMiddleware(scopeMiddleware).ToMiddleware())
```

Call `Use` before `app.Run()`. Forge copies a router's middleware into a group when the group is created, and the extension creates its group when the app starts.

## Adding plugins

Register Cortex plugins (audit hooks and so on) alongside the extension:

```go
import (
    audithook "github.com/xraph/cortex/audit_hook"
    cortexext "github.com/xraph/cortex/extension"
)

auditPlugin := audithook.New(myRecorder)

cortexExt := cortexext.New(
    cortexext.WithStore(store),
    cortexext.WithExtension(auditPlugin),
)
```

You don't need a plugin for metrics or tracing. `Register` hands the engine `app.Metrics()`, so the engine's series show up on the app's `/_/metrics` as `forge_cortex_*`, and its spans go to the tracer provider Forge installs. Pass `cortexext.WithEngineOption(engine.WithMetrics(nil))` if you want the metrics off. [Observability](/docs/infrastructure/observability) lists every span and series. The old `observability` plugin is deprecated and records nothing.

## Health checks

The extension's `Health` pings the store, and fails when the extension has no engine or no store. Forge includes it in the app's health endpoint.

## Grove database integration

When your Forge app uses the Grove extension to manage database connections, Cortex can take a `*grove.DB` from the DI container and build the right store for its driver (`pg`, `sqlite` or `mongo`). You don't import a store package for that.

### Using the default grove database

You don't have to do anything. If the container holds a default `*grove.DB`, the extension finds it and logs "cortex: auto-discovered grove.DB from container". `WithGroveDatabase("")` says the same thing explicitly, and fails `Register` when no default database is there.

### Using a named grove database

In multi-database setups, name the database:

```go
ext := cortexext.New(
    cortexext.WithGroveDatabase("cortex"),
)
```

The YAML equivalent is `grove_database: cortex`. `Register` fails if that name isn't in the container.

### Store resolution order

1. If `WithGroveDatabase` or `grove_database` is set, the named (or default) `*grove.DB` is resolved and its store is used.
2. Otherwise, if the container has a default `*grove.DB`, its store is used.
3. Otherwise, the store from `WithStore` is used.

A Grove database in the container wins over `WithStore`. If you pass your own store, don't register a Grove database the extension can find. With none of the three there's no store at all: the engine's CRUD methods return `cortex.ErrNoStore` and the health check fails. There's no in-memory fallback.

## Complete example

```go
package main

import (
    "context"
    "log"

    "github.com/xraph/forge"
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    _ "github.com/xraph/grove/drivers/pgdriver/pgmigrate"

    "github.com/xraph/cortex/api"
    "github.com/xraph/cortex/engine"
    cortexext "github.com/xraph/cortex/extension"
    pgstore "github.com/xraph/cortex/store/postgres"
)

func main() {
    ctx := context.Background()
    drv := pgdriver.New()
    if err := drv.Open(ctx, "postgres://user:pass@localhost:5432/cortex?sslmode=disable"); err != nil {
        log.Fatal(err)
    }
    db, err := grove.Open(drv)
    if err != nil {
        log.Fatal(err)
    }

    cortexExt := cortexext.New(
        cortexext.WithStore(pgstore.New(db)),
        cortexext.WithRoutes(func(eng *engine.Engine, r forge.Router) cortexext.RouteSet {
            return api.New(eng, r)
        }),
    )

    app := forge.NewApp(forge.AppConfig{
        Name:        "agents",
        HTTPAddress: ":8080",
        Extensions:  []forge.Extension{cortexExt},
    })
    app.Router().Use(forge.PureMiddleware(scopeMiddleware).ToMiddleware())

    if err := app.Run(); err != nil {
        log.Fatal(err)
    }
}
```

`scopeMiddleware` is the one from [Scope middleware](#scope-middleware). This gives you:

- the 59 REST routes under `/cortex/v1`
- migrations on startup
- health checks through `store.Ping`
- run, step and tool spans, and `forge_cortex_*` metrics on the app's scrape
- graceful shutdown with plugin notification
