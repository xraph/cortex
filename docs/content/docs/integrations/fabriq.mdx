## Overview

`fabriqbrain` (`github.com/xraph/cortex/integrations/fabriq`) adapts the
[fabriq](https://github.com/xraph/fabriq) data fabric to cortex as a
plug-n-play brain. With one wiring call your agents gain fabriq-backed:

- recall: multi-channel retrieval (vector, full-text and graph, RRF-fused,
  distillation-aware) through the engine's `knowledge_search` tool
- rich tools: `graph_traverse`, a guarded `remember`, and the distillation
  tools `map`, `digest` and `resolve`, registered as native cortex tools
- a learning loop: a plugin that writes each completed or failed run back into
  the fabric, where fabriq's embed and distillation workers turn it into future
  recall material

It's a separate module, so add it on its own:

```bash
go get github.com/xraph/cortex/integrations/fabriq@latest
```

## Wiring

```go
import (
	"github.com/xraph/cortex/engine"
	fabriqbrain "github.com/xraph/cortex/integrations/fabriq"
	"github.com/xraph/fabriq/core/agent"
	"github.com/xraph/fabriq/core/command"
)

eng, err := engine.New(append(
	[]engine.Option{engine.WithStore(store), engine.WithLLM(client)},
	fabriqbrain.EngineOptions(container,
		fabriqbrain.WithEmbedder(emb),
		fabriqbrain.WithEntities("doc", "note", "agent_memory"),
		fabriqbrain.WithWritePolicy(agent.WritePolicy{
			Allow: map[string][]command.Op{"agent_memory": {command.OpCreate}},
		}),
	)...,
)...)
```

`EngineOptions` discovers fabriq's `query.Fabric` and its entity registry from
the DI container (fabriq's Forge extension provides both). If either is missing,
or the toolkit can't be built, it returns `nil`, so the call is always safe to
include. Use `EngineOption` (singular) to wire only the knowledge provider, the
same way the Weave adapter does.

In a Forge app, pass the options through the Cortex extension with
`extension.WithEngineOption`, one per option, from code that runs after fabriq has
registered. A failure to build the toolkit (a vector dimension mismatch, say) is
only logged, so set `WithLogger` while you wire it up.

## Options

| Option | Purpose |
|---|---|
| `WithEmbedder(agent.Embedder)` | Embedding model for recall's vector channel. Must match the embedder fabriq indexed with. |
| `WithEntities(...string)` | Entity types recall searches and `ListCollections` reports. |
| `WithBudget(int)` | Token budget per recall (default 4096). |
| `WithMemoryEntity(string)` | Entity the learning loop writes to (default `agent_memory`). |
| `WithWritePolicy(agent.WritePolicy)` | Allowlist for the `remember` tool and learning-loop writes (deny-by-default). |
| `WithTenantMapper(func(ctx) ctx)` | Translate cortex request context to fabriq scope (default identity). |
| `WithRenderer(func(agent.ContextItem) string)` | Override how a recalled row becomes chunk text. |
| `WithVectorDims(int)` | Embedding dimensions the toolkit expects. Must match the embedder (for example 1536); 0 leaves fabriq's default of 768. |
| `WithLogger(log.Logger)` | go-utils logger for toolkit build failures and swallowed memory writes (default no-op). |

## Learning loop setup

To turn run activity into recall material, use the turnkey helpers in your setup:

```go
import fabriqbrain "github.com/xraph/cortex/integrations/fabriq"

// 1. Register the memory entity (dynamic, content vector-indexed).
reg.MustRegister(fabriqbrain.MemorySpec("agent_memory"))

// 2. Provision its table once (a migration, or postgres.Adapter.EnsureDynamic
//    in setup). fabriq.Open does not auto-create dynamic tables.

// 3. Allow writes to it. Pass WithMemoryEntity explicitly: it must match the
//    name used in MemorySpec above. Hosts using a non-default entity name MUST
//    pass WithMemoryEntity; the default is "agent_memory".
opts := fabriqbrain.EngineOptions(container,
	fabriqbrain.WithEmbedder(emb),
	fabriqbrain.WithEntities("agent_memory"),
	fabriqbrain.WithMemoryEntity("agent_memory"),
	fabriqbrain.WithWritePolicy(fabriqbrain.MemoryWritePolicy("agent_memory")),
)
```

The plugin writes `{content, meta}` rows to the registered entity, and fabriq's
`proj:embed` worker vectorizes `content`, and distillation rolls them up so
future recall surfaces them. As the memory corpus grows, distillation keeps
recall within budget by summarizing historical context.
