title: Plugin System
description: Lifecycle hooks for metrics, audit trails, tracing, and custom processing.

Cortex uses an opt-in plugin system where extensions subscribe to lifecycle events by implementing specific interfaces. The base interface requires only a `Name()` method, and every hook is optional.

## Base interface

```go
type Extension interface {
    Name() string
}
```

## Lifecycle hooks

There are 24 hook interfaces, grouped by category below. `RunTerminated` and `PublicationRejected` are described in [Execution outcomes and safety](/docs/execution/assurance). Extensions implement only the hooks they need.

The three run hooks after `RunFailed` carry the run's own scope on `ctx`, so a hook can read the run or queue a job under that scope. `OnRunSuspended` runs before the held asks of an agent-reply pause are released, because a fast peer could otherwise answer and resume the run while the hook is still reading it. See [Suspension](/docs/concepts/suspension#hearing-about-every-pause) and [Continuing a run from a job](/docs/execution/runs#continuing-a-run-from-a-job).

### Agent lifecycle

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `RunStarted` | `OnRunStarted(ctx, agentID, runID, input)` | Agent run begins |
| `RunCompleted` | `OnRunCompleted(ctx, agentID, runID, output, elapsed)` | Run finishes successfully |
| `RunFailed` | `OnRunFailed(ctx, agentID, runID, err)` | Run fails with error |
| `RunSuspended` | `OnRunSuspended(ctx, agentID, runID, notice)` | Run paused, for any reason: approval, external tool or agent reply. Fires after the run is `paused` and after `OnCheckpointCreated`, and before the step's held questions are released to peers |
| `RunReady` | `OnRunReady(ctx, agentID, runID, notice)` | A decision or the external results are recorded and the run waits for `ContinueRun`. Queue your job here |
| `RunReclaimable` | `OnRunReclaimable(ctx, agentID, runID, notice)` | A worker handed a run off or its lease lapsed, and the run waits for `ContinueRun` |

### Reasoning lifecycle

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `StepStarted` | `OnStepStarted(ctx, runID, stepIndex)` | Reasoning step begins |
| `StepCompleted` | `OnStepCompleted(ctx, runID, stepIndex, elapsed)` | Reasoning step finishes |

### Tool lifecycle

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `ToolCalled` | `OnToolCalled(ctx, runID, toolName, args)` | Tool invocation begins |
| `ToolCompleted` | `OnToolCompleted(ctx, runID, toolName, result, elapsed)` | Tool succeeds |
| `ToolFailed` | `OnToolFailed(ctx, runID, toolName, err)` | Tool fails |
| `ToolDenied` | `OnToolDenied(ctx, runID, toolName, reason)` | Your `ToolAuthorizer` denied the call |

Every dispatched call ends in exactly one of `ToolCompleted`, `ToolFailed` or `ToolDenied`. A call that suspends the run fires its terminal hook when the run resumes.

### Persona lifecycle

| Interface | Method | Intended to fire |
|-----------|--------|------------------|
| `PersonaResolved` | `OnPersonaResolved(ctx, agentID, personaName)` | Persona loaded for run |
| `BehaviorTriggered` | `OnBehaviorTriggered(ctx, runID, behaviorName)` | Behavior fires |
| `CognitivePhaseChanged` | `OnCognitivePhaseChanged(ctx, runID, from, to)` | Phase transition |

These three are defined, and the registry has emit methods for them, but the engine never calls those methods. Behaviors and cognitive phases aren't evaluated yet, and resolving a persona doesn't emit anything. An extension can implement them without harm; they just won't be called.

### Checkpoint lifecycle

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `CheckpointCreated` | `OnCheckpointCreated(ctx, cpID, runID, reason)` | Checkpoint created |
| `CheckpointResolved` | `OnCheckpointResolved(ctx, cpID, decision)` | Checkpoint resolved |

### Orchestration lifecycle

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `OrchestrationStarted` | `OnOrchestrationStarted(ctx, orchID, strategy)` | Multi-agent orchestration begins |
| `OrchestrationCompleted` | `OnOrchestrationCompleted(ctx, orchID, elapsed)` | Orchestration finishes |
| `AgentHandoff` | `OnAgentHandoff(ctx, orchID, from, to, payload)` | Agent-to-agent handoff |

### Messaging lifecycle

These fire when agent messaging is on (`engine.WithA2A`):

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `MessageSent` | `OnMessageSent(ctx, msgID, from, to, performative)` | A message was accepted for delivery |
| `MessageDelivered` | `OnMessageDelivered(ctx, msgID, to)` | A message reached its recipient |
| `MessageRefused` | `OnMessageRefused(ctx, msgID, to, reason)` | Delivery was refused |

### Shutdown

| Interface | Method | When it fires |
|-----------|--------|---------------|
| `Shutdown` | `OnShutdown(ctx)` | Graceful shutdown |

## Registry

The engine builds a `plugin.Registry` from the extensions you pass with `engine.WithExtension`, and `eng.Extensions()` returns it. The registry sorts extensions by hook at registration time:

```go
registry := plugin.NewRegistry(logger)
registry.Register(metricsExt)
registry.Register(auditExt)
```

When events are emitted, only extensions implementing the relevant hook are called:

```go
registry.EmitRunStarted(ctx, agentID, runID, input)
// Only calls extensions that implement RunStarted
```

## Error handling

Hook errors are logged and never propagated. Hooks run synchronously on the run's goroutine, so a slow hook slows the run:

```go
// Inside registry.EmitRunStarted:
if err := e.hook.OnRunStarted(ctx, agentID, runID, input); err != nil {
    r.logHookError("OnRunStarted", e.name, err) // a Warn with hook, extension and error fields
}
```

## Built-in extensions

- `observability.MetricsExtension`: deprecated, implements no hooks and records nothing. The engine records its own metrics and spans; see [Observability](/docs/infrastructure/observability)
- `audithook.Extension`: turns lifecycle events into an audit trail
- the `sentinel` module: evaluation through Sentinel

## Writing a custom extension

```go
type SlackNotifier struct {
    webhookURL string
}

func (s *SlackNotifier) Name() string { return "slack-notifier" }

func (s *SlackNotifier) OnRunFailed(ctx context.Context, agentID id.AgentID, runID id.AgentRunID, err error) error {
    // Send Slack notification
    return postToSlack(s.webhookURL, fmt.Sprintf("Agent %s run %s failed: %v", agentID, runID, err))
}

// Register:
eng, _ := engine.New(
    engine.WithExtension(&SlackNotifier{webhookURL: "https://hooks.slack.com/..."}),
)
```
